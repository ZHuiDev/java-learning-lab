# 从语法走向系统理解：9 个可运行实验

这些实验用图书借阅场景串起 Java 核心机制。你已经懂基本语法，建议按 `oop → collections → streams → io → concurrency → modern → reflection → jvm` 学习；`basics` 用来查漏补缺。看到输出只是观察现成代码；完成练习、解释边界、自己改出新行为，才是掌握的证据。

## 如何运行

要求 **完整 JDK 21 或更高版本**，编译目标为 21；不使用预览特性，不需要 Maven 或外部依赖。所有命令都在 `java-learning-lab` 项目根目录执行。先验证 `java -version` 与 `javac -version` 都可用，并优先使用相同 JDK。

单独编译 9 个实验（不会编译练习或依赖服务器）：

```powershell
New-Item -ItemType Directory -Force build/labs | Out-Null
$labs = Get-ChildItem src/main/java/lab/examples -Filter *.java | ForEach-Object FullName
javac -encoding UTF-8 --release 21 -d build/labs @labs
java -cp build/labs lab.examples.LabRunner
java -cp build/labs lab.examples.LabRunner oop
```

第一条 Java 命令列出实验 ID；第二条运行 OOP 实验。把最后的 `oop` 换成下表 ID 即可。网页中的运行按钮使用同一 `LabRunner.run(id)` 方法，所以网页与命令行展示的是同一组实验。返回文本各自独立，不通过 `System.setOut` 捕获全局输出。

## 每个实验怎么学

每次只做一项，用 20–40 分钟完成“预测 → 运行 → 阅读 → 修改 → 解释”。先写下预期输出，再运行验证；不要先把整份答案读完。修改前保存自己的版本，改完后重新编译。

### basics：钱为什么不能随便用 double

先预测 `5 / 2` 和 3 天逾期金额。定位 `lateFee`，解释为何金额字符串是 `"0.50"`。把天数改为 0，观察金额小数位；把天数改为负数，解释异常发生在哪里。思考：整数溢出、浮点舍入与输入不合法是三种不同问题，分别应如何验证？完成后做练习 01。

### oop：让对象保护自己的规则

同一 `Book.borrow(LoanPolicy)` 依次接收 StudentPolicy 与 TeacherPolicy，结果由具体对象决定。观察重复借阅抛出的异常。自己添加 VisitorPolicy，可借 7 天；`Book` 不应为新类型增加 if 分支。解释为什么直接公开可写的 borrowed 字段会破坏约束。这里 `record` 只是方便声明无状态策略，不要求先掌握其全部机制。

### collections：身份相同与对象相同

输入有 3 个 Book 对象，其中 2 个 ISBN 相同。预测 List 与 Set 的 size，再阅读 equals/hashCode。把身份规则暂时改成默认引用比较，预测去重如何改变；恢复后按 ISBN 反向排序。解释为什么示例使用 LinkedHashMap/LinkedHashSet（输出顺序稳定），不能依赖 HashMap 的迭代顺序。

### streams：描述计算不等于执行计算

先找创建管线的行与 `toList()` 所在行，预测访问计数从 0 变成多少。筛选条件内的计数仅帮助观察惰性，实际业务避免在中间操作加入副作用。把分组改成每类逾期天数之和。用 Optional.map/orElse 处理查询缺失，解释为什么直接 get() 可能失败；一个 Stream 被消费后不能再次消费。

### io：资源与异常一起设计

实验只在本次创建的临时目录读写两个中文书名。Path.resolve 表达路径拼接；UTF-8 显式规定文本编码。找到两个清理机制：try-with-resources 关闭 reader，finally 删除本次文件与目录。把写入行数改成 3，预测结果。思考：如果读取失败，谁负责向用户解释？若清理也失败，生产代码应怎样保留原始异常信息？

### concurrency：一次借阅必须不可分割

8 个任务竞争 3 本库存；具体成功者不确定，但成功数始终为 3、余量为 0。找到 synchronized 方法中的“判断 → 扣减”，解释把字段改成 volatile 为什么不足以让这两步原子执行。AtomicInteger 负责独立的尝试次数，Future.get 等待并传播任务异常。不要通过 Thread.sleep 猜测任务完成。虚拟线程适合大量等待型任务，不能自动增加 CPU 算力。完成后做练习 03。

### modern：让编译器帮你检查业务分支

给 sealed interface 新增一个 `Pending` 许可子类型；先不改 switch，编译器会提示哪里没有覆盖。补上对应分支。解释 record 的自动 equals 为什么让同值对象相等，也解释它不能使内部的可变 List 自动变成不可变对象。这些代码使用 Java 21 正式语言特性，不传 `--enable-preview`。

### reflection：元数据怎样变成框架行为

只有标了 `@Lesson` 的公开方法会被扫描并调用。给 helper 添加注解，重新编译观察输出。找到 RetentionPolicy.RUNTIME；若改成 SOURCE，解释为什么反射读不到。例子仅操作自有 DemoService 的公开方法，不突破访问控制。了解 InvocationTargetException 与目标方法异常的关系，再思考何时直接调用更简单。

### jvm：观察数字前先说清楚含义

String 的类加载器显示为 bootstrap (null)；实验类由应用类加载器加载。运行两次，观察堆和 GC 数字可以变化；它们是当前进程的近似/累计指标，不能当作某对象的精确大小，更不能当作性能基准。没有主动调用 System.gc。下一阶段学习 `jcmd`、JFR 与 JMH，先提出可验证的问题，再选择工具。
